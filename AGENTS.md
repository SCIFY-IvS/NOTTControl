# Project instructions

## General
- Understand existing architecture before modifying code.
- Never silently change scientific assumptions.
- Explain significant implementation decisions.
- Prefer small, testable modifications.

## Scientific computing
- Document physical assumptions and units.
- Include uncertainty propagation where relevant.
- Use reproducible analysis pipelines.
- Validate numerical results against known cases.

## Testing
- Add tests for new functionality.
- Run relevant tests after modifications.
- Report failures explicitly.
- Never claim code is validated if tests were not run.

## Documentation
- Keep README files up to date.
- Document dependencies and execution instructions.
- Record significant design decisions.
